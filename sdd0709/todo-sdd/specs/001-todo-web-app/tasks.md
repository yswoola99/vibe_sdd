# 작업 목록: 오늘의 할 일 웹 앱

**입력**: /specs/001-todo-web-app/

**사전 조건**: plan.md, spec.md, research.md, data-model.md, contracts/

> 모든 생성 문서는 한국어로 작성한다. 작업 설명, 테스트, 체크리스트도 프로젝트 Constitution의 원칙을 반영해야 한다.

## 형식

- 각 태스크는 `- [ ] T001 ...` 형식으로 작성한다.
- `[P]`는 서로 다른 파일을 수정하고 의존성이 없는 경우에만 붙인다.
- 각 태스크에는 완료 조건을 명시한다.
- 화면(UI) 작업은 API가 먼저 완성된 뒤 진행한다.

## Phase 1: Setup (공유 인프라)

**목적**: 프로젝트 초기 구조와 환경 설정

- [ ] T001 프로젝트 구조를 생성하고 app/, templates/, tests/ 디렉터리를 구성한다. 완료 조건: `app/main.py`, `app/models.py`, `app/schemas.py`, `app/crud.py`, `app/database.py`, `app/templates/index.html`, `tests/test_api.py` 파일이 존재한다.
- [ ] T002 Python 의존성(FastAPI, SQLAlchemy, pytest, python-dotenv, httpx 또는 fastapi testclient)을 설치하고 기본 환경 설정을 구성한다. 완료 조건: `pip install` 또는 프로젝트 의존성 관리 결과로 테스트 실행에 필요한 패키지가 준비되어 있다.
- [ ] T003 [P] .env.example와 .env 사용 규칙을 문서화한다. 완료 조건: `.env.example`에 `DATABASE_URL` 항목이 작성되어 있고, 저장소에 `.env`가 포함되지 않음을 확인한다.

## Phase 2: Foundational (블로킹 선행 작업)

**목적**: 사용자 스토리 구현의 기반이 되는 공통 기능

- [ ] T004 SQLite 연결과 세션 관리 로직을 구현한다. 완료 조건: `app/database.py`가 DB 세션 생성과 초기화 경로를 제공하고, 테스트에서 세션을 생성할 수 있다.
- [ ] T005 Todo ORM 모델과 데이터베이스 테이블 생성을 구현한다. 완료 조건: `Todo` 모델이 생성되고, `pytest` 테스트에서 테이블 생성 및 기본 CRUD 작업이 가능한 상태이다.
- [ ] T006 Pydantic 스키마와 CRUD 로직을 구현한다. 완료 조건: 생성/조회/수정/삭제에 필요한 입력/출력 스키마와 DB 로직이 정의되어 있다.
- [ ] T007 FastAPI 라우터를 연결해 `/api/todos`, `/api/todos/{id}`, `/health`, `/` 엔드포인트를 등록한다. 완료 조건: 각 엔드포인트가 응답을 반환하고, `GET /health`가 `200 OK`를 반환한다.

## Phase 3: User Story 1 - 할 일 생성 및 기본 목록 조회 (우선순위: P1) 🎯 MVP

**목표**: 사용자가 새 할 일을 추가하고 목록을 확인할 수 있다.

**독립 테스트**: 빈 목록에서 할 일을 하나 생성해 조회할 수 있고, 공백 입력은 거절되는지 확인한다.

### 테스트

- [ ] T008 [P] [US1] `POST /api/todos`에 빈 제목 요청을 보내 422 응답이 반환되는지 검증하는 테스트를 추가한다. 완료 조건: 해당 테스트가 통과한다.
- [ ] T009 [P] [US1] `POST /api/todos`로 새 할 일을 생성하고 `GET /api/todos`에서 조회되는지 검증하는 테스트를 추가한다. 완료 조건: 해당 테스트가 통과한다.

### 구현

- [ ] T010 [US1] 생성 API를 구현한다. 완료 조건: `POST /api/todos`가 제목을 저장하고 생성된 할 일을 반환한다.
- [ ] T011 [US1] 목록 조회 API를 구현한다. 완료 조건: `GET /api/todos`가 저장된 할 일 목록을 반환한다.
- [ ] T012 [US1] 빈 제목 입력에 대한 검증을 구현한다. 완료 조건: 빈 문자열/공백 문자열이 들어오면 422 응답과 상세 오류 메시지를 반환한다.

## Phase 4: User Story 2 - 완료 토글 및 삭제 (우선순위: P1)

**목표**: 사용자가 할 일을 완료/취소하고 삭제할 수 있다.

**독립 테스트**: 할 일을 생성한 뒤 완료 상태를 토글하고 삭제 확인 흐름이 정상 동작하는지 확인한다.

### 테스트

- [ ] T013 [P] [US2] `PATCH /api/todos/{id}`로 완료 상태를 토글하는 테스트를 추가한다. 완료 조건: 완료/미완료 전환이 성공적으로 반영된다.
- [ ] T014 [P] [US2] `DELETE /api/todos/{id}`로 삭제하는 테스트를 추가한다. 완료 조건: 삭제 성공 시 항목이 사라지고, 없는 ID 요청 시 404가 반환된다.

### 구현

- [ ] T015 [US2] 완료 토글 API를 구현한다. 완료 조건: `PATCH /api/todos/{id}`로 `completed` 값이 반영되고 저장된다.
- [ ] T016 [US2] 삭제 API를 구현한다. 완료 조건: `DELETE /api/todos/{id}`가 정상 삭제를 수행하고 없는 ID는 404를 반환한다.

## Phase 5: User Story 3 - 필터, 남은 개수, UI 및 영속성 (우선순위: P2)

**목표**: 필터와 남은 개수, 반응형 화면, 데이터 유지 기능을 완성한다.

**독립 테스트**: 상태별 필터와 남은 개수 갱신, 그리고 로컬 저장소 기반 재로드가 동작하는지 확인한다.

### 테스트

- [ ] T017 [P] [US3] `status=all|active|completed` 쿼리 파라미터에 따라 필터된 결과가 달라지는지 검증하는 테스트를 추가한다. 완료 조건: 각 상태별 응답 목록이 기대와 일치한다.
- [ ] T018 [P] [US3] `GET /`가 HTML 화면을 반환하고, 필수 UI 요소가 포함되는지 검증하는 테스트를 추가한다. 완료 조건: HTML 응답에 입력창, 필터 버튼, 남은 개수 영역이 포함된다.

### 구현

- [ ] T019 [US3] 필터 파라미터 처리와 상태별 목록 조회를 구현한다. 완료 조건: `all`, `active`, `completed`에 따라 올바른 목록이 반환된다.
- [ ] T020 [US3] 남은 할 일 개수 계산 로직을 구현한다. 완료 조건: 완료되지 않은 할 일 수가 정확하게 반환되고, 클라이언트 UI에서 표시할 수 있다.
- [ ] T021 [US3] 메인 화면 템플릿과 바닐라 JavaScript를 구현한다. 완료 조건: 페이지에서 할 일 추가/완료 토글/삭제/필터/남은 개수 갱신이 동작한다.
- [ ] T022 [US3] 브라우저 로컬 저장소를 사용해 목록과 상태를 유지하는 기능을 구현한다. 완료 조건: 새로고침 후에도 이전 목록이 재로드되고, 서버 재시작 후에도 앱이 이전 상태를 복원한다.
- [ ] T023 [US3] 모바일 화면(360px)과 빈 상태 안내를 반영한 반응형 UI를 구현한다. 완료 조건: CSS로 모바일 환경에서 레이아웃이 적절히 조정되고, 할 일이 없을 때 안내 문구가 표시된다.

## 의존성 및 실행 순서

- Phase 1 → Phase 2 → Phase 3 → Phase 4 → Phase 5 → Phase 6 순서로 진행한다.
- Phase 3과 Phase 4는 서로 독립적으로 시작 가능하지만, 공통 API 기반으로 구현한다.
- UI 작업(T021~T023)은 API 구현이 완료된 뒤 진행한다.
- `[P]` 태스크는 서로 다른 파일을 수정하거나 테스트 추가 작업으로 병렬 진행 가능하다.
