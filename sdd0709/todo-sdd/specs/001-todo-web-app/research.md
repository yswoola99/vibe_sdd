# 연구 문서: 오늘의 할 일 웹 앱

## 결정 사항

- **백엔드 프레임워크**: FastAPI를 사용한다. Python 기반으로 API 구현과 테스트가 빠르고, Pydantic 기반 요청/응답 검증이 명확하다.
- **데이터베이스**: SQLite를 사용한다. 단일 사용자, 소규모 데이터셋, 로컬 실행 환경에 적합하며 설정이 간단하다.
- **데이터베이스 경로 관리**: SQLite 파일 경로는 .env의 DATABASE_URL 환경변수로 관리한다.
- **프론트엔드 구조**: 단일 index.html과 바닐라 JavaScript, Jinja2 템플릿을 사용한다. 별도 빌드 도구 없이 빠르게 구현하고 유지보수 비용을 낮춘다.
- **UI 동작 방식**: 페이지 새로고침 없이 fetch 기반으로 API를 호출하고, 목록과 남은 개수를 동적으로 다시 렌더링한다.
- **테스트 전략**: API 경로와 상태 전환을 pytest + FastAPI TestClient로 검증한다.

## 근거

- 요구사항에는 서버 배포나 다중 사용자 동기화가 없으므로 단순한 로컬 SQLite 구성이 적합하다.
- 빈 제목 검증과 완료 토글, 삭제, 필터 같은 핵심 동작은 API 레벨에서 명확하게 테스트할 수 있다.
- 단일 HTML 페이지 방식은 요구된 반응형 UI와 빠른 구현에 적절하다.

## 검토한 대안

- **대안 1: Flask + SQLite**: 구현은 가능하지만 FastAPI의 자동 검증, Pydantic 스키마, 테스트 편의성 측면에서 FastAPI가 더 적합하다.
- **대안 2: React/Vite 프런트엔드**: 기능 요구사항을 충족할 수 있지만, 별도 빌드 도구와 프레임워크 설정이 필요해 단순성 원칙에 어긋난다.
- **대안 3: 서버 세션 기반 저장**: 요구사항상 필수는 아니며, 구현 복잡도가 높아 현재 범위에 부적절하다.
